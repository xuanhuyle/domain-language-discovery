# Deep Research Prompt 02 — Adversarial finalist review
Status: HOLD — run only after human-approved shortlist and specific finalist IDs.

Take the approved finalists, their candidate cards, source ledger, and G0–G2 statuses. Treat the proposed DSL as guilty until it proves incremental value, while refusing to reject a domain solely because competitors exist.

For each finalist:
1. Reconstruct its exact operational workflow, error costs, rule volatility and buying context; separate verified observations from hypotheses.
2. Review production approaches from best incumbents, open source, standards, mature DSLs, LLM-plus-tools, structured JSON plus conventional code. Cite original product docs or code and state known evidence limits.
3. Identify the precise domain primitive/invariant and counterexamples that are awkward, fragile or unenforceable under each alternative. A nicer syntax is insufficient.
4. Design the smallest independently answerable set of cases spanning normal, exception, conflict, temporal amendment, missing data and adversarial inputs.
5. Identify truth oracle, adjudication needs, possible leakage, test availability, and cost for one solo AI-assisted engineer.
6. Specify a preregisterable four-arm experiment (A LLM/tools; B LLM + structured code; C best incumbent rules engine/DSL; D proposed semantics), metric, threshold, negative control and kill condition.
7. Estimate potential buyer/route to market without claiming buyer validation. Note regulatory/data access barriers.
8. Give one recommendation: EXPERIMENT, HOLD FOR EVIDENCE, or STOP LANGUAGE THESIS, with a reversible rationale.

Deliver an evidence ledger, relevant links and dates, strongest counterargument, suggested next work item, and the exact fact that would change each recommendation.

Do not implement a DSL, alter the charter, change gates, fabricate interviews or imply market validation from technical performance.
